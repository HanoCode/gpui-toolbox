--surface#2C2C2E#FFFFFFsurface 卡片/面板

维度约束
字阶只有 12 / 13 / 15 / 17 / 22 五档（line-height 16 / 18 / 20 / 22 / 26）。禁止裸 px 字号，一律取 typography.xs|sm|md|lg|xl。
间距2 / 4 / 8 / 12 / 16 / 24 / 32 七档；卡片内边距 16，字段间距 12，字段内 label→控件 4。
圆角控件 6、卡片 8、弹窗 12。不要出现 4 或 10 这类非令牌值。
布局铁律操作区（参数 + 执行按钮）一律置顶，输入框沉底，结果居中——所有形态统一，不加例外；执行后焦点回输入框，结果区自动滚到顶。
悬停一律「强调色薄底」（暗 16% / 亮 10%），选中用 nav_selected；不要用灰度 hover。
按钮主按钮 = primary 底 + primary_foreground 字；次按钮 = 透明底 + 1px border；同一页面主按钮最多一个。
破坏性改名 / 替换 / 写系统文件的确认，一律走主题 Dialog（恒居中），禁用 rfd 同步模态（会 AppKit 重入并 abort）。
可访问性所有可点元素带 role + aria_label；文字可选中走 selectable_text，且 id 逐元素唯一。
长任务必须有进度 + 取消；process 轨带外取消，禁止用「等它跑完」阻塞主线程。
空态不许演示数据。空态 = 一句「做什么 → 得到什么」的操作指引。
文案所有中文串进 locales/<tag>.toml（中文源串作 key）；漏译只有 cargo test -p duck-theme 能拦住。
截断行尾说明文字（路径、版本号）必须 min_w_0().truncate()，否则长路径会把整行撑破。

二、七种页面形态所有工具都由这七种拼出来

形态结构适用
split上操作区 → 中结果 → 下输入框用于「文本进、文本出」的即时变换。参数行 + 执行按钮固定在顶部，结果居中，输入框沉底（Codex 式纵向流）。
job参数 + 进度 + 日志用于目录级长任务。操作区（参数 + 执行/取消）在顶部；参数只露前 4 项，其余收进「高级」。
pair操作区 + A/B 双栏 + 差异统计用于比对。操作区置顶，差异统计（新增/删除/修改）固定在底部，不随滚动消失。
conn操作区 + 应答/日志 + 报文输入用于网络联调。发送/格式化置顶，报文输入框沉底；日志区必须能切 Hex / 文本，且默认滚到底。
table参数 + 结果表用于检查/扫描类。工具条上给「共 N 行」与导出，表头可点排序。
form表单 + 结果预览用于配置生成。操作区置顶；右侧预览随输入实时更新，不等「生成」按钮。
preview结构树 + 详情用于解析/浏览类。导出动作随操作区置顶；左侧树固定宽 240。
这七种形态是声明式 [io] 段要能表达的上限。如果一个工具套不进任何一种，说明它需要真正的自定义界面——那就该考虑「不迁」或「只迁逻辑、宿主另做 UI」，而不是硬塞。

三、合并方案11 组 · 减少 13 个入口

合并的判断标准只有一个：两个工具是否共用同一套界面外壳与同一份数据模型。共用就合成一个「模式」开关；只是长得像但数据模型不同（比如 PDM 阅读器与金融文件解析），一律不合并——那种合并会把两个领域硬塞进一个表单，比分开更难用。

合并体成员共用的是什么代价与对策
random-gen
随机数据生成		UUID 生成 + 随机文本生成都是「填参数 → 出 N 条」，共用结果列表与复制地址 / 客户信息后置；地址生成需另评审敏感数据合成
sql-rewrite
SQL 改写		含参 SQL 替换 + SQL 可重复执行改写都是「SQL 文本进 → 可执行 SQL 出」，同一个编辑器心智幂等改写会落盘 → Dialog 确认 + .bak；参数替换纯内存
script-check
脚本检查		SQL 质量检查 + Shell 脚本检查输出同构：严重度 / 行号 / 规则 / 建议，共用一张问题表SQL 分支多「数据库类型」，按语言显隐
pkg-merge
上线包合并		SP 包合并 + 需求单合并 + v6-SEE 合并界面契约完全相同：两目录 + 范围 + 开关 + 日志客户名称仅 v6-SEE 显示；三条 Rust 路径都保留
pkg-compare
包比对		Class 代码比对 + Jar 包比对共用 zip 遍历 + class 解析 + 同一张结果表Class 粒度多两列 → 可隐藏列，不做第二张表
config-diff
配置对比		配置对比 + 配置环境对比去 SSH 后只差「粘贴 or 目录」，环境对比是配置对比的超集目录模式加「文件」列；忽略规则语法只留一套
packet-send
报文调试		TCP 请求 + XML 报文发送 + FIX 报文发送共用 transport 与 conn 骨架，差异只在编帧与校验FIX 校验和 / XML 格式化作为底部动作，按协议显隐
file-search
文件搜索		内容搜索 + 文件名搜索「找到那个文件」的两个步骤：先按名、再按内容文件名模式改遍历搜索，不做常驻索引守护
batch-edit
批量改写		批量重命名 + 批量查找替换同一套「预览 → 确认 → 应用 → 可撤销」流程重名冲突检测与替换计数各自实现，外壳共用
csv-tools
CSV 工具		CSV 表格 + CSV 转图表同一个 CSV 解析器与数据预览，先看表再画图图表模式多一条 SVG 渲染路径，仍由 JS 直接出
doc-convert
格式转换		文档转换 + XLS 批量转换都是「选输入 → 选格式 → 转换」，都依赖外部运行时运行时检测只做一次；批量模式才有统计条
合并后原工具名全部保留为别名（manifest 的 keywords），搜索「FIX」「jar 比对」「需求单」仍能直接命中，并在进入后自动切到对应模式。也就是说 发现性不受影响，界面数量减少。
