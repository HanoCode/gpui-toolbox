# SSH / 终端 / SFTP：UI 布局与操作习惯评审

> 姊妹文档：`docs/ssh-terminal-review.md`（架构与正确性，M5/M6/M7 路线图）、
> `docs/ssh-terminal-settings-render-review.md`（设置项完备性与渲染层像素缺陷）、
> `docs/tabby-deep-dive.md`（分层与组件）。
> **终版收敛见 `docs/ssh-terminal-final-plan.md`（本文的「删工具条」「满幅 55%」两处在终版已改写）。**
> 本文只回答三个问题：**布局合不合理、鼠标/触控习惯顺不顺、快捷键合不合理**。
> 所有结论带 `文件:行号`，未改任何代码。

---

## 0. 结论（三句话）

1. **骨架合理，但"每个区域都要自带一行标题"这个习惯把画布吃掉了。** 终端页固定 128px
   竖向 chrome（≈ 7.6 行终端），其中 24px 的工具条**整条都是重复信息**。
2. **交互模型是"档案优先"，不是"连接优先"。** 没有快速连接、没有最近、没有 `ssh_config` 导入；
   想连一台临时机器，必须先填 14 个字段的表单并存档。这是 SSH 客户端最贵的一个习惯错位。
3. **快捷键只在"画布有焦点"时成立。** 点一下左栏、点一下标签、点进 SFTP 面板，`⌘W/⌘F/⌘D`
   全部静默失效（不报错、不提示），属于"死键"，比没绑更伤。

## 1. 量尺：分带账本

假设 1440×900 逻辑分辨率（13" 默认）、Normal 密度、14px 等宽字号（行高 ≈16.8px）。

### 1.1 竖向（终端标签）

| 分带 | 高度 | 等价终端行 | 常驻？ | 里面装的是什么 |
| --- | --- | --- | --- | --- |
| 窗口标题栏（shell） | 40 | 2.4 行 | 是 | 应用名 + 全局搜索胶囊 |
| 标签栏 | 36（`control` 28 + `sm` 8） | 2.1 行 | 是 | 标签 + `+` + 分屏 + SFTP |
| **终端工具条** | **24** | **1.4 行** | **是** | **标题（← 标签已有）、主机（← 状态栏已有）、−/px/+/清屏** |
| 画布 | 772 | 46 行 | — | 终端网格 |
| 状态栏 | 28 | 1.7 行 | 是 | 状态点、主机、UTF-8、120×32、回滚行数、版本 |

- 固定 chrome = **128px ≈ 7.6 行**；开查找条再 −36（≈2.1 行），断线横幅再 −36。
- 横向反而宽松：默认 1440−48（活动栏）−236（左栏）= **1156 ≈ 137 列**；
  右栏展开时 856 ≈ 102 列，仍在安全区。
- **结论：竖向是稀缺资源，横向不是。** 所以"再叠一条 24px 工具条"在 13" 上等价于
  砍掉 1.4 行 `tail -f` 的输出——这笔账不划算。

> 更正上一份报告的"画布只剩约 55%"：右栏**默认是折叠的**（`duck-shell/src/view.rs:352`
> `set_collapsed(true)`），默认画布占 80.3%；只有手动展开右栏（300px）才降到 59.4%。
> 结论仍成立，但数字得按这个口径说，否则会被质疑。

### 1.2 竖向（SFTP 标签）

| 分带 | 高度 |
| --- | --- |
| 标签栏 | 36 |
| SFTP 页工具条（标题 + 上传/下载/刷新） | 24 |
| 单侧面板标题（"本机 / 12 项"）×2 行叠在同一高度 | 24 |
| 单侧路径栏（7 个图标 + 面包屑） | 28 |
| 单侧列头（名称/大小/修改时间） | 24 |
| 传输队列标题（空队列也在） | 24 |
| 状态栏 | 28 |
| **合计** | **188**（不含一条传输行 28） |

900 高的窗口里，文件列表只剩 **712px**。六个横向分带里，**有三个是"标签/标题"性质的**
（页标题、面板标题、列头），这正是"区域自带头"习惯的代价。

### 1.3 横向（谁在抢宽度）

```
1440
├ 48   活动栏（固定）
├ 236  左栏（可拖 184–340）
├ 856  画布  ← 右栏展开时
│  （默认 1156）
└ 300  右栏（可拖 260–400，默认折叠）
```

横向不是瓶颈；**但左栏 236 里只放了一个搜索框 + 三个折叠组**，信息密度偏低
（行高 28，一屏能放 ~12 条连接却只显示 3 个组头）。

**总体判断**：

| 维度 | 判定 |
| --- | --- |
| 三栏骨架（活动栏/左栏/内容/右栏） | ✅ 合理，与 VS Code 同构，不必改 |
| 终端页分带数量 | ⚠️ 多一条纯冗余工具条，建议删 |
| SFTP 分带数量 | ❌ 六条太多，可压到四条 |
| 左栏信息密度 | ⚠️ 首屏只有组头，可用性靠"点开" |
| 状态栏信息价值 | ⚠️ 五枚芯片里两枚是纯装饰（见 §2.7） |

## 2. 逐区操作习惯审查

每一区按同一套四问：**用户带着什么习惯进来 → 现在会发生什么 → 冲突在哪 → 怎么改**。

### 2.1 左栏：找连接

| 习惯 | 现状 | 判定 |
| --- | --- | --- |
| 打开应用就想"连一台机器" | 首屏：三个**全部折叠**的组头 + 搜索框 + 两个"新建连接"入口 | ⚠️ 空转 |
| 单击选中看一眼、双击才连 | **单击即连**（`render_sidebar.rs:218` → `conn.rs:130`） | ❌ 无法只查看 |
| 再点一次 = 新开一条会话 | 已经开着就**只切标签**（`conn.rs:131-134`） | ⚠️ 开第二条无处可去 |
| 最近用过的排最前 | 无"最近"、无收藏（全仓 grep 无命中） | ❌ 缺 |
| 输 `user@host:port` 直接连 | 无快速连接；唯一入口是 14 字段表单 | ❌ 最贵的缺口 |
| 搜索框：Enter 打开第一条、Esc 清空、↑↓ 选 | 搜索框**只订阅 `Change` 重绘**，无 Enter / Esc / ↑↓ | ❌ 只是过滤器 |
| 折叠的组头能看出"哪台连着" | 组头只有名字 + 数量隐藏；状态只在展开后的图标颜色上 | ⚠️ 折叠态无状态 |
| 长得放不下的连接名 | 无 tooltip，直接截断 | ⚠️ 猜 |

**根因**：左栏被设计成"档案列表"，而不是"会话入口"。档案列表的交互是"管理"，
会话入口的交互是"立刻连"。两者用同一套行组件，就出现了"单击即连但点第二次没反应"这种
半管理半连接的语义。

**改法（不动数据模型）**
1. 单击 = 选中（右侧栏切到"档案详情"），**双击 / Enter** = 连接；行尾加一个常显的"连接"图标兜底
   （不破坏"点一下就进去"的效率）。
2. 已连接的连接，行尾图标变成"再开一条"（`⌘` 点击 = 新会话），解决同主机第二会话。
3. 首屏默认展开**第一个非空组**（现在全折叠），并在最上面加一行"最近"（3 条，来自 `kv` 的最后打开时间）。
4. 搜索框补 `Enter`（打开第一条）、`Esc`（清空）、`↑↓`（在结果里移动高亮）。

### 2.2 标签栏

| 习惯 | 现状 | 判定 |
| --- | --- | --- |
| 切标签：`⌘1..9` / `⌃Tab` / `⌘⇧[` | 一个都没有；`⌘1..8` 给了全局路由，`⌘9` 空着 | ❌ |
| 标签多了横向滚 / 溢出菜单 | `overflow_x_hidden` + `flex_none` + `max_w 196`（`render_tabs.rs:13-17`），**溢出即不可达** | ❌ |
| 中键关标签 / 双击空白新建 | 都没挂（标签只有 `on_click`/`on_drag`/`context_menu`） | ❌ |
| 拖标签排序 | 拖拽被"拖入右半屏 = 分屏"独占（`render_tabs.rs:79-105`）；拖到另一个标签上无反应 | ❌ 习惯冲突 |
| 关标签有确认或可撤销 | 直接关；**没有"重开已关闭"**，会话进程一起死 | ⚠️ 误关即丢 |
| 后台标签有输出时能看出来 | 状态点只表连接；`SessionEvent::Bell` 只 `repaint = true`（`terminal_canvas.rs:807`），无未读点、无提示音 | ❌ |
| 标签名 = 我连的机器 | **OSC 0/2 会直接顶替标签标题**（`terminal_canvas.rs:878-886`）；`ResetTitle` 时回退到**当前标题**而不是档案名 → 一旦被改成 `bash`/路径，机器身份永久丢失 | ❌ 身份丢失 |
| 关闭按钮常显还是 hover 显 | **常显**，26×28 非方形紧贴标题（`render_tabs.rs:27-42`） | ⚠️ 易误点 |

**改法**
1. `⌘1..9`（页内覆盖路由）、`⌃Tab`/`⌃⇧Tab`、`⌘⇧[`/`⌘⇧]` 三套都给（见 §4）。
2. 标签栏改横向滚动 + 右侧溢出下拉（或"标签列表"按钮），永不不可达。
3. 拖拽分区：**标签栏内拖动 = 排序**，拖到画布才 = 分屏。区域不同，语义不同，用户不用学。
4. 标题改双行/双段：档案名常驻（主），OSC 标题作为次要文本（或 tooltip）；`ResetTitle` 回落到档案名。
5. 未读点：后台标签有输出/响铃时在状态点旁加一个强调色小点，切过去即清。
6. 关闭按钮 hover 才显（macOS 标签惯例），或至少把命中区收进右内边距。

### 2.3 终端工具条（建议整条删除）

`render_terminal.rs:7-113` 的全部内容：

| 元素 | 是否重复 |
| --- | --- |
| 图标 + 标签标题 | 与左边 12px 处的标签**同一个字符串** |
| 主机名 | 与下方 28px 处的状态栏**同一个字符串** |
| `−  14 px  +` | 字号控件：低频、可按键、可进右键菜单 |
| 清屏 | 已有 `⌘K`，且右键菜单也可放 |

**判定：整条删除。** 这是本次评审里唯一"删掉比改更好"的改动：
- 删掉后画布多 1.4 行，且不再出现"标签叫 prod-web-01、工具条叫 bash"（OSC 标题）这种自相矛盾；
- 字号与清屏进"右键菜单 + 状态栏右段"，能力不减；
- 与 iTerm / Terminal.app 的"终端没有工具条"这一强习惯对齐。

如果一定要保留一个"页级动作区"，就把它做成**画布右上角 hover 才出现的浮层工具簇**
（分屏 / SFTP / 清屏 / 字号），不进布局、不占行。

### 2.4 画布（终端本体）

**做对的（不要改）**：点击聚焦、`⌘`+点击开链接、双击选词/三击选行、`⌥` 拖矩形块选、
Shift 逃逸应用鼠标上报、滚轮/键盘两套滚动、拖选自动滚动、光标与网格同原点。

**习惯冲突**：

| 问题 | 细节 | 判定 |
| --- | --- | --- |
| 没有任何滚动位置指示 | 无滚动条、无"已上翻 N 行"角标、无"回到底部"按钮（全文件无 `Scrollbar`） | ❌ 上翻后不知道自己在哪 |
| 任意按键都跳回底部 | `send_encoded`/`on_terminal_key`/`paste` 全部 `scroll_to_bottom()`（`terminal_canvas.rs:1569,1633,1650,1697`） | ⚠️ 读历史时误触即丢位置，且无提示 |
| 查找条是**布局行** | `render_terminal.rs:126-133` 把查找条插在工具条与画布之间 → 打开/关闭都会改变网格尺寸，触发 SIGWINCH，shell 重排、回滚内容位置变化 | ❌ 应改浮层 |
| 查找只支持 Enter 下一个 | 无 `⌘G`/`⇧⌘G`，无"高亮全部计数随输入实时"以外的跳转习惯 | ⚠️ |
| 右键菜单只有 3 项 | 复制 / 粘贴 / 全选（`terminal_canvas.rs:2434-2468`）；缺 清屏、查找、分屏、复制路径、字号、重连 | ⚠️ 太少 |
| 右键在鼠标上报模式下也被宿主吃掉 | vim/htop 里右键不再属于应用 | ⚠️ 可接受，但应写进文档 |
| 拖文件进终端插入路径 | 画布没有 `ExternalPaths` 落点（只有远端面板有） | ❌ 高频习惯缺失 |
| 断线横幅位置 | 横幅加在画布**下方**（`split.rs:382`），画布被压短；另一份横幅加在上方（`terminal_canvas.rs:2065+`）→ 同一状态两套位置 | ❌ |

**改法**
1. 查找条改 `absolute` 浮层（右上角，宽 320，带阴影），不参与布局 → 搜索不再改变 PTY 尺寸。
2. 视口右上角常驻一个极小指示器：上翻时显示"↑ 123 行"+"回到底部"（`⌘⇧G` 或点击）。
3. 上翻状态下打字：**不静默回底**，改为回底 + 顶部闪现"已回到最新"（或跟随设置，默认回底但给反馈）。
4. 右键菜单补齐：复制 / 粘贴 / 粘贴并执行（危险项，二次确认）/ 全选 / 清屏 / 查找 / 分屏 / 复制路径 / 字号。
5. 画布接受 `ExternalPaths`：落一个文件 = 把转义后的路径打到提示符（SFTP 面板已有该模式的先例）。

### 2.5 SFTP 双栏（问题最多的一区）

| 习惯 | 现状 | 判定 |
| --- | --- | --- |
| 点一下路径就能编辑 / `⌘L` 跳转 | **没有路径输入框**；要跳目录只能开"打开目录"弹窗（`render_sftp.rs:285` → `open_directory_dialog`） | ❌ 最反习惯的一条 |
| 面包屑点任意一级 | 只保留最后 3 段，前面的收成"…"，而**"…"不可点**（`render_sftp.rs:152-167`） | ❌ 深路径只能一路"上一级" |
| 点列头排序 | 列头是纯文本，无 `on_click`；排序固定"目录优先 + 名称"（`terminal_data.rs:695`） | ❌ 长着表头的样子 |
| 多选后批量传 | `PaneState.selected: Option<String>`（`mod.rs:301`）→ **只能单选** | ❌ 批量上传/下载/删除全无 |
| 双击本地文件 = 上传到对面 | 双击本地文件 = **在访达中显示**（`sftp.rs:291-296`）；双击远端文件 = 下载 | ❌ 两侧语义不对称 |
| 双栏之间拖拽传输 | 无（只有系统文件拖入远端面板上传，`render_sftp.rs:608-621`） | ❌ |
| 传输按钮在"对象附近" | 上传/下载在**页面顶部工具条**，离选中的文件很远；分隔栏反而空着 | ⚠️ |
| 右键有"下载/复制路径/权限" | 远端行只有 重命名/删除/新建文件夹；**本地行完全没有菜单** | ❌ |
| 目录双击进入 | ✅ 有 | ✅ |
| 键盘 ↑↓/Enter/Backspace | 列表无任何键盘处理；`role(ListItem)` 有了但不可聚焦 | ❌ |
| 切换目录时列表跟着变 | `navigate` **不清空 `entries`**，只把 `loaded` 打回 false（`mod.rs:347-364`）→ 新路径下短暂显示**旧目录内容**；失败时错误提示压在旧列表上方（`render_sftp.rs:555-563`） | ❌ 会说谎 |
| 加载中有反馈 | 无 spinner / skeleton，只有一段 notice 文案 | ⚠️ |

**改法（按收益排序）**
1. **`⌘L` + 可编辑路径**（点路径栏或按 `⌘L` 变成输入框，Enter 跳转，Esc 取消）。这一步能消掉
   70% 的"打开目录"弹窗。
2. 传输箭头搬到**中间分隔栏**（↑ 上传 / ↓ 下载），双栏中间本来就有 8px 命中带 —— 零新增布局。
3. 多选：`selected: HashSet<String>` + `⌘`/`⇧` 点选 + `⌘A`；右键与传输都按集合走。
4. 双击本地面板 = **上传**（与远端对称），"在访达中显示"移到右键与 `⌘` 双击。
5. 键盘：`↑↓` 移动、`Enter` 进入/下载、`Backspace`/`⌘↑` 上一级、`⌘R` 刷新、`⌘⌫` 删除、
   `⌘⇧N` 新建文件夹。
6. 切换目录先清列表并显示"正在列举…"（一行 spinner），失败时列表为空 + 错误说明，不要旧数据垫底。
7. 列头：要么实现排序（点一次切正/倒序 + 指示箭头），要么去掉"表头"外观（改成行内分隔，不给点击暗示）。

### 2.6 传输队列

| 问题 | 细节 |
| --- | --- |
| 空队列常驻 | `render_sftp.rs:139` 无条件渲染 → 一进 SFTP 就有一条 24px 的"传输队列 0/0 个任务"空带 |
| 两处重复 | SFTP 页底部一条 + 右侧栏一条（`render_status.rs:193-221`），内容还不一样（右栏只有名字+状态） |
| 完成/失败无外部反馈 | 只改队列行状态；窗口不在前台时完全无感，也没有通知 |
| 完成项不清理 | 队列只增不减（无"清除已完成"），跑一天会堆一屏 |
| 失败原因挤在行尾 | 用 `neutral_tag(stderr 原文)` 塞在行末，长错误把行挤变形 |

**改法**：有任务才渲染；完成项 3 秒后自动淡出（保留一条"N 项已完成"摘要）；失败项常驻并给"重试 / 打开日志"；
右栏只显示"进行中 + 失败"，不重复全部；完成时发系统通知（已有 `notify` 通道）。

### 2.7 状态栏与右栏

| 问题 | 细节 | 判定 |
| --- | --- | --- |
| 五枚芯片三枚是装饰 | `UTF-8` / `120×32` / `回滚 10000 行` 都是纯文本、不可点（`render_status.rs:73-80`） | ⚠️ 长得像可点 |
| 只有版本号可选中 | 其余（尤其**路径**）不可选中、不可复制（`107` 用了 `selectable_text`，别处没有） | ❌ 不一致 |
| SFTP 双全路径 | 左右两条完整路径塞进左段（`50-64`），长路径直接把右段挤没；无 `truncate` | ❌ |
| 右侧只有一个版本号 | 一整段空白，是全局最贵的空白 | ⚠️ 可放字号/编码/回滚菜单 |
| 右栏是"会话详情" | 选中一条**未连接**的连接时，右栏仍是空态/上一个会话（`124-135`）→ 没有"档案详情"可看 | ❌ 信息架构 |
| 右栏放破坏性动作 | "删除连接"红色按钮就在"编辑连接"旁边（`275-290`），紧邻只读信息 | ⚠️ 危险动作不该在信息面板 |
| 快捷键说明是硬编码 | 文案写死 `⌘` 且漏了 `⌘F`（`332-344`），Linux/Windows 上全错；与 `app.rs` 绑定无关联 | ❌ |

**改法**：状态栏左右两段各司其职（左：状态·主机·尺寸；右：编码/回滚/字号，可点开菜单）；
路径 `truncate` + 中间省略 + 可右键复制；右栏内容由"当前选中项"驱动（选中档案看档案、选中会话看会话），
删除移到档案右键菜单；快捷键说明从绑定表生成（见 §4.4）。

## 4. 快捷键：合理性评分

### 4.1 现状（全部挂 `"Terminal"`，且 `"Terminal"` 只挂在画布元素上）

`app.rs:424-496` 一共 26 条绑定；`key_context("Terminal")` 在 `terminal_canvas.rs:2152`。

| 键 | 动作 | 评分 | 说明 |
| --- | --- | --- | --- |
| `Tab` / `⇧Tab` | 发 PTY | ✅ | 必须盖掉 Root 的焦点遍历，做法正确 |
| `Ctrl-C` | `0x03` | ✅ | 非 macOS 上盖掉 Root 的 Copy，正确 |
| `⌘= + - 0` | 字号 | ✅ | macOS 终端共识；但**不落盘** |
| `⌘K` | 清屏 | ⚠️ | 键本身对（Terminal.app 就是 `⌘K`），但与全局命令面板**同键异义** |
| `⌘D` | 分屏 | ✅ | iTerm 同键 |
| `⇧↑↓` `⇧PgUp/PgDn` | 滚动 | ✅ | 齐 |
| `⌘↑↓` | 翻页 | ⚠️ | macOS 上 `⌘↑↓` 常被理解为"到顶/到底"，这里给了翻页 |
| `⇧Home/End` `⌘Home/End` | 到顶/到底 | ✅ | |
| `⌘← →` `⌘⌫` `⌘⌦` `⌥⌫` | 行编辑 | ✅ | 与 Terminal.app / readline 一致 |
| `⌘C` `⌘V` `⌘A` | 复制/粘贴/全选 | ✅ | |
| `⌘T` | 新标签 | ❌ | 语义错：在 SSH 页开**本地 shell**；用户要的是"再连一台/同主机再来一条" |
| `⌘W` | 关标签 | ⚠️ | 语义对，**只在画布焦点下有效**（死键） |
| `⌘F` | 查找 | ⚠️ | 同上；且查找条一开就重排终端 |

**缺**：`⌘1..9`、`⌃Tab`、`⌘⇧[]`、`⌘N`、`⌘⇧T`、`⌘⇧S`、`⌘⇧K`、`⌘L`、`⌘⌥C`、`⌥⌘←→`、
`⌘G/⇧⌘G`、SFTP 全套、重开已关标签、可自定义。

### 4.2 三条"死键"与一处"错页面"

1. **死键**：焦点在左栏搜索框 / 标签栏 / SFTP 面板 / 右栏时，`⌘W`、`⌘F`、`⌘D`、`⌘K` 全部无响应，
   而且**不报错**。用户会以为"应用卡了"或"这个键不支持"。
2. **`⌘K` 一页两义**：终端里是清屏，其它页面是命令面板（`actions.rs:135` vs `app.rs` 的 `Clear`）。
   同一个键在同一个应用里换意思，是快捷键设计里最该避免的一类。
3. **`⌘R` 刷错页面**：全局 `⌘R` = `toolbox.refresh`（`actions.rs:377`）。在 SSH 页按 `⌘R` 期望
   "刷新当前面板 / 重连"，实际去刷了工具箱——没有任何反馈，因为工具箱不在前台。

### 4.3 目标键位（分两层上下文，不发明新机制）

**分层原则**：`"Terminal"` 继续只挂在**画布**上（管"发给 PTY 的键"），新增 `"TerminalPage"`
挂在**页面根**（管"页面命令"）。两者不能合并——合并后 `Tab` 会被页面上下文吃掉，
搜索框和 SFTP 列表就失去焦点遍历。

| 键 | 动作 | 上下文 | 与谁对齐 |
| --- | --- | --- | --- |
| `⌘T` | 新会话（同主机；无活动标签 → 新建连接） | Page | iTerm/Terminal.app |
| `⌘⇧T` | 新本地终端 | Page | iTerm |
| `⌘N` | 新建连接 / 快速连接 | Page | 浏览器/编辑器 |
| `⌘W` | 关闭当前标签 | Page | iTerm |
| `⌘⇧Z` | 重开已关闭标签 | Page | Chrome |
| `⌘1..9` | 切第 N 个标签 | Page | 全平台共识 |
| `⌃Tab` / `⌃⇧Tab` | 下/上一标签 | Page | 全平台共识 |
| `⌘⇧[` / `⌘⇧]` | 上/下一标签 | Page | 浏览器 |
| `⌥⌘←` / `⌥⌘→` | 焦点在左/右窗格 | Page | iTerm/OxideTerm |
| `⌘⇧S` | 打开 SFTP 面板 | Page | — |
| `⌘F` | 查找（聚焦查找框） | Page | — |
| `⌘G` / `⇧⌘G` | 下一个/上一个命中 | Page | 文本编辑器 |
| `⌘⇧K` | 清回滚（保留屏） | Canvas | Terminal.app `⌥⌘K` |
| `⌘K` | 清屏 | Canvas | Terminal.app |
| `⌘L` | 聚焦路径（SFTP） | SFTP | 浏览器/访达 |
| `⌘⌥C` | 复制当前路径（本地/远端） | SFTP | — |
| `⌘↑` / `Backspace` | 上一级目录（SFTP 列表有焦点时） | SFTP | 访达 |
| `⌘⌫` | 删除所选远端项（确认） | SFTP | 访达 |
| `⌘⇧N` | 新建文件夹 | SFTP | 访达 |
| `⌘R` | 刷新当前面板 / 重连 | Page | 需先把全局 `⌘R` 改掉 |

**冲突校验**
- `⌘1..8` 已是全局路由（`actions.rs:163-268`）；页内 `"TerminalPage"` 更深 → 终端页内 `⌘1` 切标签，
  这是**期望行为**，但必须在设置页写明"SSH 页内 `⌘1..9` = 切标签"。
- `⌘⇧D` 已给"切换主题"（`actions.rs:308`），所以分屏继续用 `⌘D`，不要动 `⇧D`。
- `⌘K`：建议**命令面板只保留 `⌘⇧P`**（面板角标也改成 `⌘⇧P`），把 `⌘K` 完整让给终端；
  想要"两处都能开面板"的，就在非终端页保留 `⌘K` 作为别名，但**终端上下文里必须唯一**。
- `⌘R`：把全局 `toolbox.refresh` 改成"刷新当前路由"的分发（或挪到 `⌘⇧R`），否则 SFTP 的 `⌘R` 永远别扭。
- `⌘W`：当前 shell 没有 `⌘W` 关窗绑定，所以页面级 `⌘W` 安全；将来若加关窗，用 `⌘⇧W`。

### 4.4 让说明自动跟着绑定走

右栏那段硬编码文案（`render_status.rs:332-344`）必须换掉：在 `app.rs` 的绑定表旁边放一张
`const TERMINAL_KEYS: &[(&str, &str)]`（动作 id + 键），**绑定与说明同源**，渲染时按平台把
`$mod` 换成 `⌘`/`Ctrl`。这样漏 `⌘F`、写死 `⌘`、改了键不更新说明这三类问题一次性消失。
