# 数据库模块 vs DBX 差距分析（页面 / 操作 / 功能）

> 对比对象：本仓 `crates/duck-app/src/pages/db` + `crates/duck-db`（约 46k 行 UI）↔ `temp/dbx`（Vue 桌面端，51 个组件目录 / 487 个 `.vue`）。
> 口径：只看**数据库工作区**（连接 → 浏览 → 查询 → 改数据 → 改结构 → 专项工具），不看 Redis 独立页、邮件、SSH 等其它模块。
> 依据：本仓源码 + `docs/database-design.md` §4.4–§4.23；DBX 源码 `apps/desktop/src/components/{grid,editor,layout,sidebar,structure,...}` 与 `docs/content/docs/*.cn.mdx`。
> 结论只写**已核实**的差异；本仓已对位的能力不重复罗列。

---

## 0. 一页结论

本仓已经完成「DBX 主链路」的对位：连接档案（四档传输 / 只读 / 环境 / 钩子）、对象树九档 + 九类右键菜单、SQL 编辑器（逐条执行 / 选区执行 / 诊断 / 事务两态 / 超时三级）、结果网格（四视图 / 暂存编辑 / 批量改删 / 列筛选 / 复制格式矩阵）、表结构五标签草稿编辑、ER / 比较 / 传输 / 实例 / 仪表板 / AI。**差距不在「有没有」，而在三处：交互粒度、可视化密度、专项工具的完成度。**

按影响排序的十条（详细论证见后文）：

| # | 差距 | 现状一句话 | 等级 |
|---|---|---|---|
| 1 | **无矩形单元格选区** | 只有「整行勾选 + 单格选中」，没有拖拽选区、没有选区 SUM/AVG/单元格数 | P0 |
| 2 | **排序只有单列** | `SortSpec` 单值，无多列优先级、无「仅当前页排序 / 数据库排序」区分、无排序构建器 | P0 |
| 3 | **无列冻结 / 列重排** | 列宽可拖、可隐藏、可重置，但首列不冻结、列序不可拖 | P0 |
| 4 | **网格布局不落盘** | 列宽、密度、隐藏列、树展开态都是「这一次看库」的会话态，重启回默认 | P0 |
| 5 | **无自动刷新** | 表浏览只能手点刷新；DBX 为 5/10/30/60/300s + 环形倒计时 | P1 |
| 6 | **导入只有 CSV 直落库** | 无预览、无列映射、无编码选择、无类型推断；DBX 支持 8 种格式 + 多文件批量建表 | P1 |
| 7 | **表结构缺「约束 / 分区」两页** | 五标签：DDL / 字段 / 索引 / 外键 / 触发器；字段级缺生成列、枚举列表、SRID、标识列 | P1 |
| 8 | **三个常驻灰按钮** | 「比较架构 / 数据库备份 / MCP 设置」`disabled(true)`，无解释（`shell.rs:507/535/545`） | P1 |
| 9 | **编辑器缺导航类交互** | 无查找替换面板、无跳行、无 Ctrl+Click 表名跳转、无表结构 peek、无拖表入编辑器、无执行目标选择器 | P1 |
| 10 | **标签与快捷键面窄** | 10 条键位；标签不可拖拽/拆分/独立窗口/固定；无 ⌘1..9 / ⌘W / ⌘F / ⌘P | P2 |

## 1. 整体骨架：五区对五区

### 1.1 布局映射

| 区域 | DBX | 本仓 | 结构差异 |
|---|---|---|---|
| 顶部 | 全局工具条（新建连接/查询/驱动/插件/MCP/主题/置顶/缩放） | 全局操作条：新建连接 / 新建查询 / 数据传输 / 驱动管理 / 执行 SQL 文件 / 比较架构 / 比较数据 / 数据库备份 / MCP / 刷新 / AI（`shell.rs:363-602`） | 本仓把「传输 / 比较 / 备份 / MCP」**放进了全局条**，DBX 放在对象树右键与设置里；前者更显眼，但三个是灰的，等于长期占位 |
| 左栏 | 连接分组 → 连接 → 库 → schema → 表/视图 → 字段/索引（虚拟滚动 + 正则 + 定位 + 可见范围） | `SidebarPanel` 184–340（默认 236），顶部「搜索连接与对象…」，按「用户组 → 档案分组 → 默认组」分段（`browse.rs:661-1513`） | 本仓**没有**正则开关、类型搜索、定位按钮、列表选项图标；搜索是单一输入框 |
| 中栏 | 标签栏（可折叠 / 可拆 / 可独立窗口）+ 编辑器 / 结果区分割 | 标签条 + 上下分栏（`v_resizable("db-sql-split")`，默认各半）+ 8 种 mode 提前返回（`shell.rs:906-1151`） | 本仓标签**只支持关闭族**；分栏只有上下一种，没有左右并排、没有嵌套组 |
| 右栏 | AI 右面板 + 网格内「表信息」抽屉 + 详情弹层 | shell 级 5 段 dock：Detail / History / Cell / Builder / Ai（`mod.rs:2016`、`render_sidebar.rs`） | 本仓把「详情 / 单元格 / 构建器 / AI」统一成同一条 dock，切换成本低；DBX 是「上下文抽屉」，不占常驻宽度 |
| 底部 | 无全局状态栏；读数在结果表格底栏 | 全局状态栏：状态 / 事务中+提交回滚 / 待提交 N 条 / N 个连接 / 失败徽标（`shell.rs:1213-1314`） | 本仓多一条全局状态栏（DBX 用户迁移过来会觉得「信息更集中」，但占 1 行高度） |
| 浮层 | Toast / 通知中心 | 底部居中 toast，2s（`TOAST_LIFETIME`），max_w 520 | 本仓 toast 更短、更窄；DBX 有可回溯通知（导出/备份进度独立 popover） |

### 1.2 骨架层面的实质差距

1. **标签不是「工作区」**：DBX 的标签可固定、重命名、复制、拆分右移/下移、拖出成独立窗口、成组着色；本仓标签只有「关闭 / 关闭其他 / 关闭右侧 / 关闭全部 / 复制名称」（`render_tabs.rs:169-240`）。这不是装饰差异——它决定了**多任务并行**的上限：本仓无法两个表并排比对。
2. **分栏是二选一，不是可组合**：本仓只有「编辑器 ↔ 结果」上下分栏（可各自收合）；DBX 是 splitpanes，支持多编辑组左右并排、组内再上下分。
3. **右栏承载过重**：本仓 5 段 dock 里 Detail 段串了「命名空间 picker → 新建表 → 连接信息 → 命名空间卡 → DDL 卡 → 行数/列/索引/外键/触发器 → 选中行编辑器」七块（`render_sidebar.rs:11-307`）。DBX 把这些拆成「表信息抽屉（网格内）+ 结构页 + 详情弹层」，**同一屏的信息密度更低**。本仓 236px 宽 + 260px 定高滚动卡，长 DDL 与宽表信息都在抢同一列。

## 2. 数据网格：差距最密集的一层

DBX 网格是它最成熟的部分（`components/grid/` 43 个组件）。本仓网格已有四视图、暂存编辑、批量条、列筛选、复制格式矩阵，但**操作模型不同**：本仓是「行 × 单格」，DBX 是「单元格矩阵」。

### 2.1 选择模型（P0）

| 能力 | DBX | 本仓 |
|---|---|---|
| 选区 | 单元格 / 矩形区域拖选 / 整行 / 多行 / 整列 | 单格 + 行首复选框（`checked_rows`），`⌘A` 全选行 |
| 选区读数 | 底栏实时 `SUM / AVG` + 单元格数 + 行数，数值**可点击复制**（`DataGridPagination.vue`） | 底栏只有「N 行 / 耗时 / 命中 / 已达上限」（`grid.rs:342-411`） |
| 选区复制 | 按选区矩阵复制，支持 TSV/CSV/JSON/Markdown/SQL IN/WHERE 等 13 种 | 复制整行 / 复制所选 N 行 / 复制单元格（`grid.rs` 菜单） |
| 区域操作 | 选区批量改、区域填充、选区导出 | 批量条只作用于「勾选行」（`grid.rs:3869-4005`） |

**影响**：取一列数算合计、复制一块交叉表、把一段结果贴进 Excel——这三个高频动作在本仓都要绕路（导出 CSV 再算）。

### 2.2 列与布局（P0）

| 能力 | DBX | 本仓 |
|---|---|---|
| 列宽 | 拖边界、双击按内容自适应、`content / fill` 两种宽度模式 | 拖 4px 把手、组件内 `auto_fit_column`（`grid.rs` 注释：已搬进 `DataTableState`） |
| 列序 | 拖列头重排，按表/查询持久化 | **不可重排**（只有隐藏 / 重置） |
| 冻结 | 冻结当前列 / 冻结到某列 / 冻结选中列 / 增量冻结 / 取消（`useDataGridColumnLayout.ts`） | **无** |
| 密度 | 紧凑 / 标准 / 宽松 | 全站统一 density token，网格无独立三档 |
| 字体字号 | 表格独立字体 + 字号（`DataGridFontFamilyControl.vue`） | 跟随主题字阶（`builtin::base_tokens`），无网格覆盖 |
| 表头 | 可显示字段注释 / 数据类型；悬浮说明可关 | 只显示列名（类型在单元格详情/右栏看） |
| 类型配色 | 按数据类型着色，可跟随主题或自定义方案（增删改复制） | **无** |
| 列布局弹层 | 显示/隐藏 + 搜索（列名与注释）+ 反选 + 重置顺序 + 至少保留一列 | 隐藏列 + 「全部显示」+「至少要保留一列可见」 |
| 持久化 | 列宽/列序/隐藏/冻结按表或按查询记住 | 列宽在组件内存，隐藏列是页面态（`hidden_columns`），重启即失 |

### 2.3 筛选与排序（P0）

| 能力 | DBX | 本仓 |
|---|---|---|
| 排序 | 多字段排序构建器：拖拽排序、启用/禁用、「仅排序此项」、SQL 预览与复制 | `SortSpec` 单值；表头菜单三档（升/降/清除） |
| 排序语义 | 明确区分**数据库排序**（重新查询）与**当前页排序**（仅本地） | 只有一种：表浏览走 `page_order` 重新取数，查询结果走本地排序 |
| 筛选视图 | 三视图：快捷 popover / 条件视图 / 文本视图；条件可拖拽排序、启停 | 条件列表 +「添加条件 / 清空」（列选择 + 值） |
| 运算符 | 14 种（含包含 / 不包含 / 介于 / 列表内 / 为空 / 不为空） | 本仓按列类型给「为空 / 不为空」等，但无完整运算符矩阵 |
| 手工 WHERE | 搜索框直接输入 WHERE 条件并「应用 WHERE」 | 表浏览无 WHERE 输入口（只能靠筛选条） |
| 本地值筛选 | distinct 值清单，可「筛选此值 / 排除此值 / 仅 NULL / 仅非 NULL」 | 有「本地值筛选」与「数据库值筛选」（`grid.rs` 串），但入口分散在列头下拉 |
| 搜索 | 搜索框支持「过滤 / 高亮」两种模式，`Ctrl+F` 聚焦 | 结果搜索只有过滤语义（`result_search_text`），`⌘F` 未绑定 |

### 2.4 编辑与写回（P1）

| 能力 | DBX | 本仓 |
|---|---|---|
| 单元格编辑器 | 按类型分派：枚举下拉 / 日期时间选择器 / 布尔 / JSON / 二进制（可从文件导入）/ 图片几何只读 | 通用文本编辑 + JSON 校验（`JSON 不合法`）+ 默认值预设 |
| 行状态 | 新增 / 更新 / 删除三态，底部「N 项待保存」 | 暂存三态 +「待提交 N 条」+ 64 步撤销 |
| 新增行 | 新增行 / 插入多行（位置：上/下/末尾）/ 粘贴为新行（TSV、INSERT 自动匹配列）/ 克隆为新行（可排除主键） | 「新增行」+ 右栏填写；支持粘贴单元格、`⌘V` |
| 全表更新 | 「按 WHERE 更新全部匹配行」，先预览影响行数，确认后执行（含未加载行，明确告知无回滚） | **无**；只能逐行或勾选当前页行 |
| 保存前预览 | 展示生成的 INSERT/UPDATE/DELETE | 只显示条数（「提交 N 条暂存改动」） |
| 只读原因 | 列头 / 详情里说明（Join / 聚合 / 无主键 / 只读连接 / 驱动不支持） | 统一一句「需要单表 + 主键齐全」 |
| 大字段 | 按需加载（需主键或虚拟唯一键）；JSON 格式化 / 原值 diff / HEX+ASCII / 图片 / 几何地图 | 单元格详情有原始值、JSON 预览、HEX 复制/导出；无查看器、无按需加载（大字段随页取） |

### 2.5 分页与刷新

| 能力 | DBX | 本仓 |
|---|---|---|
| 每页条数 | 50/100/500/1000 + 自定义 1–1,000,000，默认 100 | `[100,200,500,1000,2000]`（`mod.rs:237`） |
| 分页器 | 首页/上页/页码输入/下页/末页 +「加载全部并转到末行」+ 无限滚动模式 | `« ‹ [页码] › »`（`grid.rs:419-589`），`»` 在总数未知时恒灰 |
| 总数 | 「统计总行数」按需触发 | 表浏览用元信息估算「约 N 行」，无按需精确统计 |
| 自动刷新 | 5/10/30/60/300s，按钮环形倒计时 + `Ns`，有未保存编辑时阻止 | **无**（`自动刷新` 零命中） |

## 3. SQL 编辑器：能力齐、导航弱

本仓已有：逐条执行 + 执行列状态机、选区执行、格式化 / 压缩 / 注释、关键字小写、自动换行、语义诊断条（最多 3 条 + 总数）、执行计划、执行文件（进度条）、保存查询、历史、事务两态、超时三级、AI 修错/解释。这些与 DBX 主链路等价。

差距集中在「在编辑器里少走路」：

| 能力 | DBX | 本仓 |
|---|---|---|
| 查找替换 | `⌘F` / `⌘R` 完整面板：上一个/下一个、区分大小写、正则、选区内、全部选中 | 无面板、无键位 |
| 跳行 | `⌘⌥G` | 无 |
| 表名导航 | `⌘/Ctrl+Click` 表名 → 打开数据或定位对象 | 无 |
| 结构 peek | 悬浮表名显示结构卡，双击字段插入 | 无（需切右栏或表结构 tab） |
| 拖拽 | 树里的表/字段拖进编辑器生成引用 | 无 `on_drop` |
| 意图动作 | `⇧⌘↵`：展开 `*`、限定/取消限定标识符、批量限定 | 无 |
| 执行目标 | 执行目标选择器（当前/全部），多库多连接目标组、并行/串行、合并结果 | 只有「连接 + 库/Schema」两个下拉 |
| 变更预览 | UPDATE/INSERT/DELETE 改写为只读 SELECT 干跑，`列名 (new)`、待删行 | 无（只能手动改写） |
| 参数化 | 识别 `?` `:name` `${name}` `#{name}` `@name` `@set`，执行前参数对话框 | 无（`参数化` 仅 1 处注释命中） |
| 片段 | 触发键 + Tab 跳占位符；内置 sel/ins/upd/cte/join | 只有「已保存查询」（整条 SQL，非片段） |
| 诊断呈现 | 错误行内装饰 + 「定位错误（第 N 行，第 M 列）」可点 | 仅底部条，**无内联下划线**（设计 §4.18.1 已自述是实质差距），行列不可点 |
| 结果归档 | 保存/导入结果集（run 归档） | 无 |
| 执行摘要页 | 语句 / SQL / 状态 / 返回行 / 耗时 / 行列，单击预览双击定位 | 有「执行过程」页，字段较少 |
| 多结果 | 「全部结果 (N)」+ 每个 run 可重命名/固定/关闭左右 | 多语句结果可切换（「看哪一份」），无固定/重命名 |

## 4. 表结构编辑器：本仓五页 vs DBX 七页

本仓（`structure.rs`）：目标条 → 属性条（仅 MySQL：引擎/字符集/排序规则）→ 五标签（DDL / 字段 / 索引 / 外键 / 触发器，带脏点与计数）→ SQL 预览卡（可折叠 + 复制）→ 底部应用条。字段网格九列、可拖拽重排、可复制其他表字段、可拖列宽、默认值预设、密度三档。**DDL 页可编辑**（`编辑 SQL`）。

| 能力 | DBX | 本仓 |
|---|---|---|
| 页签 | 字段 / 索引 / 外键 / **约束** / 触发器 / **分区** / DDL | 缺「约束」「分区」两页 |
| 字段级 | 长度单位、精度/Scale、自增、字符集/排序规则、生成列（表达式 + VIRTUAL/STORED）、枚举值列表、几何+SRID、标识列（seed/increment）、扩展属性、所有者 | 有：名/类型/长度/可空/主键/默认/注释/字符集/排序规则/唯一 |
| 索引 | 普通/唯一/主键/全文/空间/复合、包含列、过滤条件、**并发创建**（PG）、重建、自动命名 | 有新增/删除/重建/组成列；无并发建索引、无包含列、无过滤条件 |
| 分区 | RANGE/LIST/HASH + 分区键/表达式 + 附加/分离（`CONCURRENTLY`）+ 待应用操作列表 | **无** |
| 表选项 | 存储引擎、自增起始值、下一个自增值、注释 | 有引擎/字符集/排序规则；自增起始值在树右键生成语句 |
| 危险确认 | 删字段、收紧 NULL、改类型、改主键、物理重排、重建表分别确认；SQLite 走 CAST 重建 | 统一一句「表结构变更不会自动回滚，确定继续吗？」+ `guard_dangerous` |
| DDL 与结构冲突 | DDL 页与结构页同时改 → 阻止保存 | 本仓是「先执行 DDL 页，再执行生成的 ALTER」（有提示），语义不同但可预期 |
| 引擎能力闸门 | 能力不足隐藏或只读 | `attrs_known` 按引擎禁用可空/主键/默认/注释；外键/索引有「该引擎不支持」提示 |

**缺口性质**：不是「不能用」，而是**建表/改表的表达能力上限**——生成列、枚举、分区、并发索引这四类在真实项目里常见，现在只能写 SQL。

## 5. 对象树与连接：功能密度高，但搜索/选择弱

本仓树已有九档对象（表/视图/索引/过程/函数/触发器/事件/序列/用户）、九类右键菜单（含复制表/粘贴表/克隆为新表/重命名/清空/截断/VACUUM/自增起始值/生成 4 种 SQL 骨架/导出表结构/数据字典/ER/权限/进程/仪表盘/加入 AI）。连接表单已覆盖四档传输、只读/读写、环境（开发/预发布/生产）、钩子、可见数据库、分组。

差距：

| 能力 | DBX | 本仓 |
|---|---|---|

## 8. 全局交互

### 8.1 快捷键（本仓 10 条 vs DBX 30+）

本仓 `bind_keys`（`mod.rs:442-498`）：`⌘↵` 执行/停止、`⌘.` 停止、`⌘S` 提交暂存、`⌘⇧⌫` 丢弃、`⌘C/⌘A/⌘X/⌘V`、`⌘Z/⌘⇧Z`。

DBX 另有（本仓无）：`⌘W` 关标签、`⌘T` 新查询、`⌘1..9` 定位标签、`⇧⌘[ ]` 左右切换、`Ctrl+Tab` 切换器、`⌘P` 快速打开、`⌘F/⌘R` 查找替换、`⌘⌥G` 跳行、`F2` 编辑单元格、`F5` 刷新、`Delete` 删行、`⌘⇧D` 编辑结构、`Tab` 转置、`⌘D` 复制行、`⌥↑/↓` 移行、`⌘/` 行注释、`⇧⌥A` 块注释、`⌘B` 侧栏、`⌘⇧I` AI 面板。

⚠️ 本仓 `⌘S` 语义是「提交暂存改动」，与主流 SQL 客户端「保存脚本」相反（设计里已注明原因：编辑器不占 `⌘S`）。迁移用户会误触。

### 8.2 布局持久化（P0）

- 本仓不落盘：`tree_open`、`pinned_tables`（`shell.rs:299-300`）、结果列宽（组件内存）、结构列宽（`StructureDraft.column_widths`）、隐藏列、侧栏宽度以外的分栏比例。
- DBX：列宽/列序/隐藏/冻结按表或按查询记忆；标签组布局、标签顺序、侧栏展开态跨会话保留。
- 影响：每次重启都要重新摆一遍宽表列宽与树展开——这是「每天都疼」的成本。

### 8.3 空态与错误

本仓同一类失败有三种落点：toast（`charts.rs`）、页内文案（`grid.rs`）、状态栏（`browse.rs`）。DBX 统一走 toast + 结果区错误条。建议统一为「页内错误条 + 可复制详情 + trace_id」，toast 只用于成功回执。

## 9. 本仓相对 DBX 的优势（不要在对位中丢掉）

1. **中文源串即键的 i18n 体系** + 编译期装载，英文覆盖有单测守卫（DBX 是运行时 JSON）。
2. **审计日志 + trace_id**：失败徽标可跳到对应审计行，DBX 无跨入口关联。
3. **连接钩子四相位**（Pre/PostConnect、Pre/PostDisconnect）+ 超时 + 失败策略，DBX 无。
4. **连接档案导入**：直接吃 DBeaver `data-sources.json` 与 TablePlus `.tableplusconnection`，DBX 只有自家格式。
5. **驱动管理带国内镜像 + 摘要校验 + 批量更新**。
6. **数据字典导出**（Markdown/TSV）比 DBX 的 DBML 更贴近「交付给非技术同事」。
7. **原生 GPUI 渲染**：无 WebView，dev 档已优化依赖（1/3），release 档 1000×20 网格 7ms。
8. **红色上涨/绿色下跌之外的金融化格式**（千分位、列统计）已在网格内。

## 10. 建议的补齐顺序（按「每天都会用到」排序）

### P0（1–2 周量级，全部是网格内核 + 状态）

1. **单元格矩阵选区**：`selection: Option<CellRect>` + 拖拽 + 底栏 SUM/AVG/单元格数（可复制）+ 选区复制矩阵。复用现有 `visible_columns` 与格式化管线，不碰内核。
2. **多列排序**：`SortSpec` → `Vec<SortKey>`，表头菜单「添加到排序」+ 排序条（可拖优先级、可删）；表浏览把 `page_order` 拼成 `ORDER BY a ASC, b DESC`。
3. **列冻结 + 列重排**：冻结 = 渲染时把前 N 列拆成独立固定层（DataTable 组件已有列宽/滚动抽象）；重排 = 拖列头写回列序，随会话持久化。
4. **网格布局持久化**：按 `connection_id + object` 存一个 kv 键（结构同 `Appearance`：全 `Option` + `serde(default)`），含列宽/列序/隐藏/冻结/密度/页大小。
5. **给三个灰按钮一个交代**：短期把「比较架构 / 数据库备份 / MCP」从全局条移除（或点击弹「路线图」说明），不要长期灰着占位。

### P1（体验一致性）

6. 自动刷新（5/10/30/60/300s，环形倒计时，脏数据时暂停）。
7. CSV 导入向导：预览前 50 行 → 列映射 → 空串/NULL 策略 → 批大小 → 结果回执；导出补 XLSX 与「当前页/全部/选中行」范围。
8. 表结构补「约束」「分区」两页 + 字段级生成列/枚举/SRID/标识列。
9. 编辑器导航：查找替换面板（`⌘F/⌘R`）、跳行（`⌘⌥G`）、表结构 peek（复用右栏 Detail 卡）、Ctrl+Click 表名、拖表入编辑器。
10. 标签与键位：`⌘W` / `⌘T` / `⌘1..9` / `⌘F`；标签拖拽重排；至少支持「左右拆分」一种并排。
11. 命令面板：复用 `palette_pages` 的注册表，加「表/连接/已保存查询」三类条目。

### P2（专项工具）

12. ER 升级为可编辑画布（自动布局 + 缩放 + 导出 SVG/PNG + 同步 DDL）。
13. Schema Diff 从禁用变可用（可先只做「对象存在性 + DDL 文本差异」，不做重命名检测）。
14. 备份：先做「立即备份（导出 SQL/ZIP）+ 恢复」，计划备份延后。
15. 字段血缘、数据库文档笔记、慢查询、kill 会话、数据生成、只读临时解锁、生产逐次确认。
