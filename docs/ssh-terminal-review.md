# SSH / 终端 / SFTP 架构评审（架构师视角）

> 评审对象：`duck-ssh`(2.7K) + `duck-term`(3.4K) + `pages/terminal/`(5.6K) + `pages/terminal_canvas.rs`(3.5K)
> + `terminal_data.rs`(1.2K) + `terminal_dialogs.rs`(1.6K)，合计约 **18K 行**。
> 参考基线：`temp/oxideterm`（GPL-3.0，88 个 member 的 SSH/Mosh/SFTP 工作区）、
> `temp/zed`（`Terminal` 上下文键位与渲染）、`temp/FluxDown`（UI 规格）。
> 说明：`temp/starship` **不是 SSH/SFTP 终端**，它是 shell 提示符（prompt）项目，
> 不含连接、会话、文件传输任何一层；本评审只借用它「配置文件优先 + 预设可切换」的产品思路，
> 不作功能对照（如另有 `temp/` 下的同类工具请指出，我按同一口径补评）。
>
> 结论分三级：**P0 = 现在就会让用户踩到**（正确性 / 阻塞）、**P1 = 明显缺失**、
> **P2 = 一致性与打磨**。每条给证据（`文件:行`）与修法，不做无据推断。

> 同系列另三份：`docs/ssh-terminal-ui-review.md`（布局/鼠标/快捷键）、
> `docs/ssh-terminal-settings-render-review.md`（设置项完备性 / 字体与编码 / 渲染像素缺陷）、

## 0. TL;DR

现有实现的**骨架是健康的**：内核零 GPUI、单向分层、单一真源、错误文案单一出口、
known_hosts 只读的取舍有据、口令不入 argv。问题不在「哪里写错了」，而在三处**结构性欠账**：

1. **SFTP 不是 SFTP**。它是「每次操作 fork 一个 `ssh` + 文本协议」，功能上限=shell 能做的事，
   延迟=一次进程+一次往返，且**没有超时、没有取消**。这是当前最大的能力天花板。
2. **连接生命周期缺一层**。没有连接对象/运行时的概念：复用靠 `ControlPath` 哈希隐式约定，
   于是「编辑连接后参数不生效」「转发被先连上的 SFTP 吃掉」这类问题只能靠注释提醒，
   而不能靠结构保证。
3. **键盘是半成品**。终端内键位相当完整（对齐 zed），但**应用级导航几乎为零**：
   没有标签切换（`⌘1..9`/`⌃Tab`）、没有快速连接、`⌘T` 只开本地 shell、
   `⌘K` 在终端内是清屏、在页面其它位置是命令面板（同一页面两种含义）。

| 维度 | 评分 | 一句话 |
| --- | --- | --- |
| 分层与可测性 | ★★★★☆ | 零 gpui 内核 + 纯函数决策 + 单测钉不变量，很好 |
| 连接管理 | ★★☆☆☆ | 档案够用，缺导入/快速连接/会话恢复/运行时 |
| 终端仿真 | ★★★★☆ | alacritty 网格 + 鼠标/焦点/IME/OSC 52/133 都在，缺通知与未读 |
| SFTP | ★★☆☆☆ | 能用但慢、单文件、无权限/无预览/无批量 |
| 传输 | ★★☆☆☆ | 有队列/取消/重试，缺并发控制、暂停、速率、ETA |
| 转发 | ★★☆☆☆ | 配置面完整，运行时不可见、存在复用竞态 |
| 快捷键 | ★★☆☆☆ | 终端内齐、应用级缺、`⌘K` 语义分裂 |
| UI 布局 | ★★★☆☆ | 三栏信息密度合理，标签栏溢出与右栏文案是短板 |

**Top 8 必修**（详见 §4）：SFTP 无超时/无取消、ControlMaster 参数失效、后台标签不自愈、
双份断线横幅、`⌘K` 冲突、标签溢出不可达、粘贴无危险确认、同主机不能开第二个标签。

## 1. 现状架构快照

```
duck-app/pages/terminal/*            视图 + 页面状态（profiles / tabs / panes / transfers）
        │  ▲ cx.spawn + background_executor
        ▼  │ Task 回主线程 notify
duck-ssh（零 gpui，纯 argv + 进程）    Target::argv / exec / list_dir / scp / probe
        │
        ▼ std::process
系统 ssh（OpenSSH）── ControlMaster ──┬─ 终端 PTY（ssh -t）
                                     └─ 每次操作一条 channel（exec / scp）

duck-term（零 gpui）  alacritty Term + 真实 PTY + 事件循环线程
        ▲
terminal_canvas.rs    自绘 Element（网格 / 选区 / 光标 / 链接 / 搜索高亮 / 命令标记）
```

三条关键路径的**判断是对的**，值得保留：

- **驱动系统 `ssh` 而非自研协议**：直接继承 `~/.ssh/config`、agent、ProxyJump、MFA、
  `known_hosts` 与用户自己的 `StrictHostKeyChecking`，fail-closed 且不替用户决策
  （`crates/duck-ssh/src/lib.rs:1-40`、`known_hosts.rs:1-30`）。
- **认证收窄只看用户选择**（`AuthMethod`），不看字段有没有值 —— 这条修掉了
  `MaxAuthTries` 被 agent 钥匙吃光的经典坑（`target.rs:114-136`、`:272-332`，含回归测试）。
- **传输句柄与 UI 线程解耦**：`*_spawn` 拆出「起进程」与「等结果」，取消是真 kill
  （`remote.rs:20-30`、`transfer.rs:146-289`）。

代价也要说清楚，后续所有讨论都建立在这三条代价上：

| 代价 | 表现 | 影响面 |
| --- | --- | --- |
| 每个远端操作 = 一个进程 | SFTP 列举/改名的固定开销 ≈ fork + 一次 SSH 往返 | 目录浏览手感、批量操作 |
| 只有「终端 + 单命令」两档 | 拿不到 SFTP 协议能力（属性、符号链接、原子 rename、部分读） | 文件管理功能上限 |
| 连接级选项由「第一个连上的人」决定 | 转发/agent 转发/编辑后参数可能静默不生效 | 见 §4.2 |

## 3. 设计不合理（结构性，非 bug）

这一节只列「改一个函数修不好、需要动结构」的项。

### 3.1 没有「连接运行时」这一层

现在「连接」= 一条 `StoredProfile`（数据）+ 一个 `sessions: HashMap<String, TerminalSession>`
（终端 PTY）。中间那层**连接运行时**（谁握着 master、转发状态、重连计数、SFTP 通道、健康度）
不存在，于是它被拆散到三处隐式约定里：

- 复用靠 `control_path(socket_dir, target)` 的哈希（`target.rs:523-529`）——只 hash
  `destination + port + identity`；
- 转发靠「先开终端」的顺序（`target.rs:333-349` 的注释自己承认了这个坑）；
- 重连靠 `TerminalSession.respawn` 的快照（`terminal_canvas.rs:179-186`）。

**后果**：任何「连接级」的新能力（转发开关、健康检查、SFTP 通道复用、录制）
都要再往这三处各补一次判断，且没有一处能回答「这台主机现在到底连没连、几条通道、转发在不在」。

**修法**：引入 `ConnectionRuntime`（id → { master 是否活、控制 socket 路径、转发进程句柄、
重连状态、通道数 }），`open_connection` 从「建标签」升级为「请求一个运行时」。
这是唯一能同时解决 §4.2 / §4.4 / §5.5 的结构性改动。

### 3.2 `⌘K` 一页两义

- 全局命令面板：`actions.rs:110-113`（`$mod-k`）；
- 终端上下文清屏：`app.rs:437`，并在 `actions.rs:56-59` 用注释承认「会撞车所以只在 Terminal 上下文覆盖」。

于是**同一页面**里，焦点在画布上 `⌘K` = 清屏，焦点在左栏搜索框/空态时 `⌘K` = 命令面板。
用户无法建立肌肉记忆，且 macOS Terminal 用户的 `⌘K` 预期是清屏 —— 面板抢走它反而是错的。

**修法**：清屏保留 `⌘K`（与 macOS Terminal 一致），命令面板改为 `⌘⇧P` 单一入口
（`$mod-k` 从 `ActionMeta::keys` 移除）。这是**纯注册表改动**，不动逻辑。

### 3.3 `⌘T` 在 SSH 页面开本地 shell

`app.rs:490` → `NewTab` → `terminal_canvas.rs:2279` → `new_local_tab`。
用户在一堆远程会话里按 `⌘T`，得到的是本机 zsh —— 与 iTerm/Termius/OxideTerm 的预期
（「同一主机再来一个会话」或「新建连接」）相反。而「同主机第二个会话」又恰好被
`open_connection` 去重挡掉（§4.8）。

**修法**：`⌘T` = 复制当前会话（同 `Target`、新 PTY）；`⌘⇧T` = 新建本地 shell；
`⌘N` = 新建/快速连接。三条动作都在 `actions.rs` 里加，成本极低。

### 3.4 字号有两条真源

- 设置页写 `kv: terminal.settings.font_size`（`module_settings.rs:80`、`:140-160`）；
- 页面运行时 `nudge_font_size` 只改内存（`terminal/mod.rs:628-635`），**从不写回**。

结果：用户按 `⌘+` 调到舒服的字号，重启后回到设置值；而设置页又显示着另一个数字。
`helpers.rs:5-15` 的注释把这条解释成「设置是下次进来的默认值」，但 UI 上没有任何地方表达
「这是默认值，当前会话是临时值」。

**修法**：`⌘+ / ⌘-` 直接写 `terminal.settings.font_size`（去抖 + `flush`），
设置页成为唯一真源的展示面。`⌘0` 清空该字段回到跟随主题。

### 3.5 「无会话」被当成「已断开」

`LinkStatus` 只有三态（`terminal_data.rs:46-60`），`link_status()` 对「不在会话表里」
返回 `Disconnected`（`terminal/tabs.rs:176-182`）。于是**从未连过**的连接在左栏就是红点
「已断开」—— 用户会以为它刚掉线。

**修法**：加 `LinkStatus::Idle`（灰点，文案「未连接」）。四态与语义一一对应：
未连接 / 连接中 / 已连接 / 已断开。这是显示层改动，风险低。

### 3.6 页面上下文（`"Terminal"`）绑的是画布，不是页面

所有终端键位都挂在画布元素的 `key_context("Terminal")` 上（`terminal_canvas.rs`）。
焦点一旦离开画布（点左栏连接、点 SFTP 面板、点工具条），`⌘D`/`⌘F`/`⌘W` 全部失效。
SFTP 标签**更是完全没有键盘**：没有刷新、没有删除、没有上传/下载、没有上下移动。

**修法**：页面外壳也挂 `key_context("Terminal")`（画布已是更深层，冲突键仍在画布内覆盖），
再给 SFTP 面板一套 `"Sftp"` 上下文键位（见 §7）。

## 4. P0：现在就会踩到

### 4.1 SFTP 的每次操作都无超时、无取消

`remote::exec` 用 `Command::output()` 阻塞等待（`remote.rs:87-135`），**没有 `ConnectTimeout`、
没有整体超时、没有中止句柄**；`list_dir` 直接调它（`remote.rs:226-239`）。
网络抖动/黑洞时，这次列举会占住一条 `background_executor` 线程直到 OS 级 TCP 超时（可达 75s+），
界面上只有「还没加载」—— 且用户无法取消。

同时 `Target::options` 在 UI 层**恒为空**（`conn.rs:110`），所以连 `-o ConnectTimeout=10`
这种一行修法都没接上。

**修法**（两档）：
1. 立刻：`common_argv` 固定加 `-o ConnectTimeout=10`（对终端会话无害，`ssh -t` 也只是更早报错）；
2. 正确：`exec` 改为 `spawn` + 轮询/超时 kill（复用 `TransferHandle` 已有的模式），
   列表页给「取消」；`list_dir` 全面改走持久 SFTP 通道后此问题自然消失（§4.2）。

### 4.2 ControlMaster 让「连接级参数」静默不生效

`control_path` 只 hash `destination + port + identity`（`target.rs:523-529`），
而 `apply_edit` 只摘会话、**不结束 master**（`conn.rs:322-334`）。
`ControlPersist=300`（`target.rs:266`）意味着：

- 改了端口转发 / `ForwardAgent` / 口令后重连 → **复用旧 master，新参数一个都不生效**，最长 5 分钟；
- 先开 SFTP 再开终端 → master 由 `exec`/`scp` 建立，**转发参数压根没上去**
  （`target.rs:333-349` 的注释已记录同类事故，但只覆盖了 `ForwardAgent`）。

**修法**：
1. `control_path` 的哈希纳入「会影响连接级行为的字段」（forwards、agent_forwarding）；
2. `apply_edit` / `reconnect` / 删除档案时执行 `ssh -O exit -o ControlPath=… <dest>` 收掉 master；
3. 理想解：转发由独立的 `ssh -N` 守护进程持有（`ConnectionRuntime` 的一部分），
   与终端/SFTP 通道解耦 —— 这样「先连谁」不再影响结果。

### 4.3 切标签会掐掉后台标签的自动重连

`activate()` 主动撤销**其他标签**的重连计时（`terminal/tabs.rs:10-25`，注释直言
「用户已经看向另一个标签，后台不该还在按退避起 ssh」）。
对「盯着一个标签等它恢复」是合理的，但真实用法是「开 8 个会话，去干别的，回来发现全断了且没重连」。
连接状态不该由视图焦点决定。

**修法**：只在「标签关闭 / 档案删除 / 用户手动停止」时撤销；切标签只影响**提示的显眼程度**。

### 4.4 断线提示有两份，文案与按钮都不一样

- 画布内绝对定位横幅：`terminal_canvas.rs:2065-2115`（按钮「重连」，第二行显示
  「自动重连中…」/「已停止自动重连。」）；
- 画布外附加条：`terminal/render_terminal.rs:308-346`（按钮「重新连接」，注释写
  **「不做自动重连」** —— 与上一处的自动重连完全矛盾）。

两者会同时出现（`split.rs:377-383` 在 `is_exited()` 时追加第二条），用户看到两个「连接已断开」。

**修法**：删掉 `render_reconnect_bar`，把「状态 + 次数 + 倒计时 + 主按钮」统一进画布横幅；
文案改成「第 2/5 次，8 秒后重试」—— 现在 `Pending` 只说「自动重连中…」，用户不知道还要等多久。

### 4.5 标签栏溢出后不可达

标签行是 `flex_1 + overflow_x_hidden`，每个标签 `flex_none + max_w(196)`
（`render_tabs.rs:10-18`、`:57`）。开够 6~8 个标签后，右侧的标签**被裁掉且无法滚动**，
只剩 `+` / 分屏 / SFTP 三个固定按钮。没有溢出菜单、没有横向滚动、没有「标签列表」下拉。

**修法**（按成本排序）：标签行改横向滚动（`overflow_x_scroll`）→ 再补一个「▾ 全部标签」
下拉（复用 `searchable_menu`，与全仓一致）。

### 4.6 粘贴不设防

`paste_clipboard` 直接把剪贴板文本写进 PTY（`terminal_canvas.rs:1561-1572`），
内核的括号粘贴（`session.rs:1746` 起有测试）只解决「应用能识别这是一次粘贴」，
**不解决「多行内容会被逐行执行」**。对一个连生产服务器的工具，这是最贵的一类事故。

**修法**：粘贴内容含 `\r`/`\n` 且不止一行时，弹主题 `Dialog` 确认（列出前 N 行 +
「共 M 行」）；设置里给「始终确认 / 仅多行确认 / 从不确认」，默认「仅多行」。

### 4.7 目录列举的解析边界

`list_command` 用 `\t` 分隔四段、`\n` 分行（`remote.rs:200-217`、`parse_listing:296-320`）。
文件名里含 **制表符或换行**时，这一行会被错切（名字被截断、多出一条假条目）。
另外每个文件要 fork 两次（`wc -c` + `date -r`），1000 文件的目录 ≈ 2000 次进程创建，
即使有 `ControlMaster` 也慢；UI 端再截断到 400 条（`terminal_data.rs:41`），
**超出的既看不到也没有分页**。

**修法**：改持久 SFTP 通道后一次 `readdir` 全拿到（含属性），这三个问题同时消失。
过渡期可把分隔符换成不可打印字节（`\x1f`）并对名字做 `tr` 转义，成本也低。

### 4.8 同一主机开不了第二个会话

`open_connection` 命中已有标签就只切过去（`conn.rs:134-138`），注释把它当特性
（「同一主机开两条会话是无意的重复连接」）。但：分屏可以（`open_split_with`）、
OxideTerm/iTerm/Termius 都允许，而「同主机第二个会话」恰恰是最常见的用法
（一边 `tail -f`、一边操作）。

**修法**：标签 id 与连接 id 解耦（`<conn_id>#<n>`，与分屏的 `<id>#2` 同族），
左栏单击 = 复用/新建由设置决定（默认「已开则聚焦」，`⌘T`/右键「新建会话」强制新建）。

## 5. P1：缺失能力（按投入产出排序）

### 5.1 连接管理

| 缺什么 | 现状 | 建议 |
| --- | --- | --- |
| 快速连接 | 只能走「新建连接」弹窗并落库 | 工具条/`⌘N` 一个输入框，`user@host:port` 解析即连；可「保存为连接」 |
| `~/.ssh/config` 导入 | 手填别名（系统 ssh 认得，但界面发现不了） | 只读扫描 + 列出 Host 别名 + 「导入为档案」；**不要**做自动同步（会与用户手改打架） |
| 命令面板里的连接 | 只有 8 条固定动作（`actions.rs:395-506`） | 连接列表动态进面板（「打开 生产-1」），这是最快的一次可达性提升 |
| 会话恢复 | 重启回到空页（`mod.rs:582-584` 有意为之） | 记住上次标签集合，启动时显示为「灰态可恢复」，点击才连（不自动连） |
| 连接元信息 | 只有 `group` | 加 `tags` / `color`（左栏点色更快的识别），与 OxideTerm 对齐 |
| 最近使用 | 无 | 左栏顶部「最近」分组（按最近打开时间，最多 5 条） |

### 5.2 终端细节

- **通知与未读**：无 bell 处理（全仓无 `Bell` 分支）、无「后台标签有新输出」标记。
  标签只有状态点（`render_tabs.rs:200-207`）。建议：`SessionEvent` 加 `Bell`；
  非激活标签收到输出/铃声 → 标签上打小圆点或 `●`；`⌘⇧U` 跳到最近未读。
- **Shell 集成没有入口**：内核已解析 `OSC 133`（`session.rs:140-165`、`prompt_bars`），
  画布已画命令标记（`terminal_canvas.rs:1938-1948`），但**没有任何地方帮用户装 shell 集成**。
  远端 shell 不吐 `OSC 133`，这条能力在 SSH 上等于不存在。建议：设置页给一段可复制的
  `PROMPT_COMMAND`/`precmd` 片段 + 「复制到剪贴板」，并在检测到「标记数为 0」时于画布角落提示一次。
- **命令完成通知**：有 `ShellMark::CommandFinished(exit)` 却没有 UI 消费它做「长命令完成提醒」。
  接上 5.2 的通知即可（>10s 的命令结束时发一条系统通知）。
- **选择**：有拖选、越界自动滚动、全选、双击（`mouse.rs`），缺「双击选词 / 三击选行」与
  「矩形选择」。后两者是运维高频（选一列 PID）。
- **滚动**：有 `Shift+PgUp` 与滚轮；缺「滚到底部」悬浮按钮与「输出时暂停跟随」指示
  （用户往上翻时新输出会把视口顶走 —— 现在靠 `scroll_to_bottom` 的时机，缺显式状态）。
- **显示设置**：只有字号/字体/行高/内边距（`module_settings.rs:78-94`）；缺光标形状（beam/block/underline）、
  闪烁开关、`bell` 行为、`⌥` 作为 Meta 的开关（macOS 上 `⌥b` 是 `∫` 还是 `ESC b` 必须可选）。

### 5.3 SFTP / 文件管理

- **单选**：`PaneState.selected: Option<String>`（`mod.rs:300`）。批量上传/下载/删除做不了。
  建议改 `BTreeSet<String>` + `⌘/⇧` 多选 + 表头全选。
- **隐藏文件**：列举脚本**总是**包含 `.[!.]*`（`remote.rs:204`），没有开关。
  macOS 惯例是默认隐藏。建议加工具栏「显示隐藏文件」开关（默认关，状态进 `PaneState`）。
- **排序 / 过滤**：`sort_entries` 固定（目录优先 + 名字）。缺列头点击排序、缺文件名过滤框。
  两者都能在本地做完（数据已在内存），成本极低。
- **属性**：无权限列、无 chmod、无所有者。建议先加只读列（SFTP 通道建立后顺手就有），
  chmod 放右键菜单，走 `PendingAction` 确认。
- **预览**：双击远端文件 = 下载到本地当前目录（`sftp.rs:297-300`），语义偏「隐式下载」。
  建议双击 = 预览（文本前 100KB / 图片），右键菜单里明确「下载到…」。
- **不对称**：本地面板双击 = 在访达显示；远端双击 = 下载。两侧同一手势两种语义，
  且本地面板没有任何写操作（刻意，见注释）。建议本地面板至少补「删除/重命名/新建」
  中的「新建文件夹」（上传前的取材区经常要建目录）。
- **面包屑**：只显示最后 3 段（`render_sftp.rs:152-166`），缺「可编辑路径栏」。
  运维场景粘贴路径 >> 点面包屑。建议 `⌘L` 把面包屑切成输入框。

### 5.4 传输

- 无**并发控制**：每次入队立刻起一个 `scp`（`transfer.rs:53-73`）。10 个小文件 = 10 个进程，
  抢带宽也抢 `ControlMaster`。建议串行队列 + 可配并发（默认 1）。
- 无**速率 / ETA / 剩余时间**：进度只有百分比（`Transfer` 结构里没有速率字段）。
  300ms 轮询已有字节数（`PROGRESS_POLL`），算速率是纯本地数学。
- 无**暂停/继续**：`scp` 不支持，只能取消后重传。要么接受（并在 UI 上说清「取消=重传」），
  要么换 SFTP 通道后实现 offset 续传。
- 队列**不持久化**：`transfer_handles` 是页面字段（`terminal/mod.rs:498`），重启后既没有记录、
  也无法再取消上一轮遗留的 `scp`。风险确认一下即可 —— 建议入队时记 pid 到 `kv`，启动时清理孤儿。

### 5.5 转发 / 认证

- **转发在运行时不可见**：档案里配了 `-L` 就只能等命令失败才知道它没起来。
  建议 `ConnectionRuntime` 里记录转发子进程 + 端口，右栏给一栏「隧道」列表（本地端口 / 目标 / 状态）。
- **无跳板机字段**：`ProxyJump` 只能写进 `~/.ssh/config`。`Target.options` 是现成的透传口
  （`target.rs:350-353`），补一个「高级选项」多行输入即可（不做链式可视化编辑器）。
- **无 TOTP**：`keyboard-interactive` 会在 PTY 里问，用户手输 —— 可用，但每次新建会话都要输。
  这是 OxideTerm 的差异点，成本中等（密钥存 vault、提示匹配、生成 6 位码），放 P2。
- **私钥要手填路径**：`key_file` 是字符串输入。补一个文件选择（走 `file_dialogs.rs`，禁 rfd 同步模态）。
- **主机密钥**：只有告警文案（`terminal_canvas.rs:2966-3100`），没有「展示指纹 / 移除旧记录」的动作。
  建议告警条上给「复制 `ssh-keygen -R host` 命令」按钮（不改 `known_hosts`，守住只读取舍）。

### 5.6 快捷键（详见 §7）

缺：标签切换（`⌘1..9`/`⌃Tab`/`⌘⇧[]`）、快速连接、复制当前路径、复制为纯文本、
重开已关闭标签、SFTP 面板全套键位、可配置快捷键 UI。

## 8. 终端细节（已做对的与仍缺的）

**已做对**（不要再改）：

- 网格与光标、选区、条带高亮共享同一原点（`terminal_canvas.rs` 的注释链完整记录了两个坑）；

5. 「输出时暂停跟随」的显式状态与「回到底部」按钮；
6. 选中内容的「复制为纯文本 / 保留软换行」选项（`copy_selection` 现在只有一种口径）；
7. 终端右键菜单（复制/粘贴/搜索/清屏/分屏/关闭）—— 现在画布没有右键菜单，用户只能记快捷键。

## 9. 路线图

### M5「正确性与安全」（建议先做，纯修复，无新概念）

1. `ConnectTimeout=10` + `exec` 超时/取消（§4.1）
2. `control_path` 纳入连接级字段 + 编辑后 `ssh -O exit`（§4.2）
3. 删掉重复断线横幅，统一为一份带次数/倒计时的横幅（§4.4）
4. `⌘K` 让位命令面板；`⌘T` 改「新会话」、`⌘⇧T` 本地 shell（§3.2/§3.3）
5. 多行粘贴确认（§4.6）
6. `LinkStatus::Idle`（§3.5）
7. 标签栏滚动（§4.5）
8. 字号写回设置（§3.4）
9. 右栏快捷键说明改为「从绑定表生成」（§6）

**验收**：断网 3 秒内 SFTP 面板给出可操作错误；改转发后重连必生效；8 个标签全部可点达；
`⌘K` 在整页语义一致。

### M6「连接运行时 + 持久 SFTP」（结构性，收益最大）

1. `ConnectionRuntime`（§3.1）：master 生命周期、通道计数、转发子进程、健康状态；
2. 持久 SFTP 会话替换「每次 fork」（§4.1/§4.7）：目录列举改 `readdir`，
   带属性/符号链接；`scan_dir` 取代 `LIST_LIMIT=400`；
3. 传输队列：并发=1 串行、速率/ETA、暂停（SFTP 通道下可续传）；
4. 转发可见化（右栏「隧道」）+ 独立 `ssh -N` 进程；
5. 快速连接 + `~/.ssh/config` 只读导入 + 命令面板里的连接条目。

**验收**：1000 文件目录列举 < 300ms 且可取消；`/usr/bin` 不截断；批量传 20 个文件串行不抢带宽。

### M7「手感与协作」

1. 标签切换/新建/重开全套键位 + 可配置键位 UI；
2. 通知 / 未读 / 命令完成提醒 + shell 集成片段一键复制；
3. SFTP 多选、排序、过滤、隐藏文件开关、权限列、预览；
4. 终端：光标形状、`⌥` Meta、右键菜单、选词/选行；
5. 会话恢复（灰态可恢复，不自动连）；
6. 广播输入（P2）。

---

## 10. 明确**不**建议做（防止过度设计）

| 不做 | 理由 |
| --- | --- |
| 自研 SSH 协议栈 / 换 russh | 现有路线换来的是「用户全部登录能力 + fail-closed」，这是最大资产；只在 SFTP 一处需要协议能力，局部引入即可 |
| 内置代码编辑器 / IDE 工作区 | 与工具箱定位冲突；最多做「只读预览」 |
| tmux 控制模式、Mosh、串口、RDP/VNC | 各自是一个子系统，收益/成本比低 |
| 云端同步连接档案 | 口令已在本地 vault，同步会引入密钥托管问题 |
| 「自动展开分组 / 自动连接上次会话」 | 与「界面禁演示数据」同一条纪律：默认不替用户做有副作用的决定 |
| 给主机密钥校验加开关 | 安全基线不做成可关项（与仓库既有口径一致） |
