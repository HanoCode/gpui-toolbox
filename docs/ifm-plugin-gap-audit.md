# 已集成插件的「参考仓功能对齐」审查（2026-10-18）

> 触发：用户指出「工具命名和参考项目不一样」「支持的功能不一样，没完全复刻过来，
> 比如密码加解密参考项目支持很多类型、可以 tab 切换，现在就只有几个」。
>
> 本文是**逐插件审查的台账**：每个工具在参考仓里对应哪个页面、那个页面有多大、
> 我们现在的 `[io]` 声明有几个可调项、结论是什么。**判据是「入口数量」不是
> 「功能数量」**——它能高效地把「明显没搬全」的工具挑出来，但一个参数背后可能
> 藏着很多逻辑（`SQL 质量检查` 只有 1 个参数，规则却有上百条）。所以「行数 ≥
> 我们的 5 倍」只列为**待核实**，结论必须回到页面上逐条读。

## 一、审查方法

1. 参考仓 `src/tools/index.ts` 给出 `工具 id → .vue` 的映射，`src/composables/tools.ts`
   给出 `id → 中文名`；本仓 `plugins/<族>-<工具>/plugin.toml` 给出 `中文名 → [io]`。
   两边以**中文名**连接（工具命名已按参考仓对齐，见第三节）。
2. 统计参考页的「功能面」：总行数、`<button>` 数、`const x = ref(` 数、`<SelectBox>` 数。
3. 统计本仓插件的「可调面」：`[[tools.io.params]]` 条数、`{ value = ... }` 选项数。
4. 比值明显失衡的（参考页 ≥ 400 行而我们 ≤ 3 个参数）回页面逐段核对。

1. **HTTP 请求**：据「34 个按钮」推测的 **代理 / 客户端证书 / 断言** 三项，参考页
   `HttpRequest.vue` 里**并不存在** —— 它只调

   多标签 / 编辑器增删行。
2. **SQL 合并**：据「规则开关在页面上」推测的 **去重 / 编码 / 账户映射** 也不存在 ——
   页面只有三个输入框，去重（`dedupe_keep_newest_by`）与编码
   （`read_file_auto_encoding`）都在后端硬编码。
3. **Class · Jar 比对**：据「12 个按钮、630 行」推测的「多 class 版本选择、反编译视图」
   只对了一半 —— 反编译视图（`get_class_source` / `compute_source_diff`）确实存在，
   但**没有**「多 class 版本选择」；12 个按钮是「选目录 2 · 开始 / 取消 / 重新对比 3 ·
   筛选 5 · 日志/结果 2」。

结论：判能力先 grep 一次 `invoke(` 与页面上的 `v-model`，再数按钮。

### 已收口（本轮）

- **Class 代码比对 · Jar 包代码比对**：两个页面是同一个骨架（`ClassCompare.vue`
  630 行、`JarCompare.vue` 510 行，逐行比对过：工具栏、统计条、筛选条、日志/结果
  两个 tab、分页、导出，连 `filters` 数组都一样，只有 jar 多一个「缺失」）。
  逐件对上：① **环境下拉**（上线包 / 生产包 / 测试包 / 下发包 / 自定义）→
  `env_a` / `env_b` 两个 `select` + `env_a_custom` / `env_b_custom` 两个文本框
  （「自定义」是哨兵值 `custom`，`select` 的选项不许是空串）；② **统计条**
  （新增/升级/回退/异常/相同/总计）→ 报告头部一行，jar 多一项「缺失」；
  ③ **筛选按钮** → `view`（`all` / `abnormal` / `update` / `rollback` / `new` /
  `same`，jar 多 `missing`），`all` **不含相同**（几百条同版本会把要看的埋掉，
  想看相同显式选它 —— 与源页唯一的渲染差异）；④ **结果表 9 / 8 列** →
  分组逐行（服务 / 类名 / 包名 / 两边版本 / 级差；jar 是 服务 / 路径 / 两边版本 /
  两边类数），`状态` 由分组标题承担，`差异描述` 由两边版本 + 级差表达；
  ⑤ **导出 CSV / Excel** → `csv_dir`：源页这两个按钮**都是 CSV**
  （`exportExcel` 也是 `write_text_file` + `.csv`，只是引号风格不同），本仓只留一份
  正确的（UTF-8 BOM、RFC 4180 转义、按严重程度排序），表头随界面语言；
  ⑥ **日志 tab + 进度条** → `progress` 事件；⑦ **`compare_lib` 默认值**对齐源页
  （jar 默认勾上 = 放开扫描范围；class 例外，见下）。
  **不迁三件**：源码级 diff（`java -jar cfr.jar`，插件进程没有 JRE）、分页
  （200 条/页是滚动容器的产物，纯文本一次给全）、「重新对比（强制刷新缓存）」
  （本工具没有跨次缓存，每次都真扫）。
  ⚠️ **一处有意偏离**：class 的 `compare_lib` 默认**不勾**（源页默认勾）。lib 条目的
  「版本」是 `jar:<大小>:<修改时间>` 指纹 —— 两个包只要打包时间不同，每个 lib JAR
  都会变成一条「升级/回退」，把真正要看的类差异埋掉。理由写在 `plugin.toml` 里。
- **SQL 合并**：参考页 620 行、7 个按钮，拆开只有「选目录 → 开始 → 看统计」一条线；
  三个输入框（`src_dir` / `customer_no` / `dbType`）本来就已对齐，后端 2,101 行
  在 `duck-sql-core/src/sql_merge.rs` 里是整段复刻（2,126 行，含 ZIP 解压、
  SPSQL 容器分组、`ddl` 单独成组、GBK 自动解码、同名文件取最新 mtime 去重）。
  本轮补的是**结果形态**三件：① 每组下面那张**五列表**
  （来源包 / 源文件 / 合并到 / SQL 条数 / 大小，Markdown，贴工单不用再排）；
  ② 条数校验**正负两档都给**（源仓只在失败时打黄标，看起来像「没校验」；
  文案不写「= 各源文件之和」——DML 组末尾会自动补 `COMMIT;`，core 判定允许多 1 条）；
  ③ 参考页标题栏那个 **「?」帮助弹窗**（功能 / 操作 / 三种目录结构 / 结果目录）
  落成 `guide` 开关，勾上只输出说明、不读目录不写盘 —— 执行页没有弹窗容器，
  而这份说明的实质是「目录怎么摆」，能复制留存比弹一下就没更有用。
  因此 `src_dir` 摘掉 `required`（否则勾了 `guide` 也会被宿主必填校验挡住），
  空目录改由工具层报「请选择要合并的源目录」。
- **HTTP 请求**：参考页是 Postman 式工作台（1,518 行），拆开看只有
  「单请求」那一段能迁进「跑一次看结果」的形态，其余是**多请求容器**。
  逐件对上：① **Params 标签** → `query`（键值表，值百分号编码后拼到 URL，
  `#fragment` 保持最后）；② **变量插值** → `vars`（`{{名字}}`，**未定义即报错**，
  参考页静默替换成空串会让请求打到 `https:///api`）；③ **Body 五态** →
  `body_type`（`none` / `raw` / `x-www-form-urlencoded` / `form-data` / `binary`），
  raw 的 JSON/XML/HTML/Text 由 `body_format` 只决定默认 `Content-Type`；
  ④ **form-data 的「文件」勾选** → `字段=@路径`（本仓输入是文本框，用约定代替勾选框，
  multipart 边界每次现生成、文件字段按扩展名猜 `Content-Type`）；
  ⑤ **API Key 放 header / query** → `key_in`（参考页 `authApiIn`，二选一，
  不会同时发）；⑥ **Import cURL** → `source = curl`：`tokenizeCurl` + `parseCurl`
  移植进内核（含 `$'...'` ANSI-C 引用、`-G` 把体搬进查询串、`-d` 自动升 POST、
  `-u` / `-b` / `-A` / `-e` / `-k`），解析结果**直接发**并在报告回显来源；
  ⑦ **Response 的 Body / Headers / Cookies 三个子标签** → 报告按段展开，
  `set-cookie` 逐条解成 name/value/domain/path/expires/max-age/secure/httponly/samesite；
  ⑧ **耗时 / 体积** → `耗时 ms · 体积 KB`（1024 进制，收 `u64`）。
  **不迁的容器**：集合 / 文件夹 / 多标签 / 环境变量管理器 / 集合导入导出 ——
  全部要持久化多份请求，与「一次运行」冲突；历史仍然只留最近 20 条
  **方法·地址·状态·耗时**，且地址**连查询串一起去掉**（`key_in = query` 的 API Key
  就在查询串里，落盘即泄露），比参考页把 `Authorization` 写进 localStorage 更保守。
  ⚠️ 框架缺口两处（**不是**本插件少写参数）：① `[io.params]` 的 `text` 是
  **单行**输入（宿主 `InputState` 没开 `multi_line`），所以 query / 表单用
  `a=1&b=2` 连写，`values` 里的 `&` 要写 `%26`；② `[io.fields]` 没有
  「按参数显隐的第二个文本域」，cURL 命令只能粘在同一个底部输入框里
  （label 写成「请求体 / cURL 命令」）。
- **Hosts 管理**：参考页右侧七个标签页，五个落成参数、两个按形态取舍。逐件对上：
  ① **方案清单**（对应左栏卡片）—— 启用状态 / 名称 / 环境 / 负责人 / 变更单 / 条数 /
  域名，元信息从文件头读（`# name:` / `# env:` / `# owner:` / `# ticket:` /
  `# desc:` / `# enabled: false`）；② **校验**分成两段：逐方案（哪个文件自己写错了）
  + 合并结果（**跨方案冲突**只在这一段能看出来），同一行同样的错误不重复报；
  ③ **查找替换**（`keyword` + `replace_to`），查找扫全部方案含停用的、注释行也算，
  替换是字面量替换；④ **方案对比**（`diff_a` / `diff_b`，slug 或方案名都能写）；
  ⑤ **同步与应用**（沿用已有的命令生成 + 系统 hosts 对比）。
  **四处形态取舍**（写在模块头与 `plugin.toml`）：**历史留痕** / **回收站** /
  **导出导入备份 JSON** / **环境单选切换**。前三条在「一个方案 = 一个文件」之后
  都有更耐用的替代（mtime 与版本库、`rm` 后的系统回收站、`cp -r` 整个目录）；
  第四条是跨文件的状态规则，插件一次运行只看一眼目录，没有「上一次谁开着」可依据 ——
  要单环境就只留一个文件写 `# enabled: true`、其余写 false，规则留在文件里，
  `git diff` 能看见。
  ⚠️ 替换**不回写原目录**：结果写到 `replace_out` 指定的另一个目录（与原目录相同
  直接拒绝）—— 一次点运行改掉用户五个文件，风险与收益不成比例。
- **速查手册**：参考页不是「一张更长的卡片」，是 **navi 形态的浏览器**。逐件对上：
  ① `cheat-parser.ts`（188 行）整段移植成 `duck-misc-core/src/cheat.rs`（navi 语法
  一条不落：`%` 标签 / `#` 描述 / `$ var: =a|b|c` 静态候选 / `$ var: <命令>` 动态候选 /
  `\` 续行）；② 20 张表（参考仓 `cheat-sheets-data.ts` 2390 行，含 5 张带命令模板）
  由 `scripts/gen_cheat_sheets.py` 转成 `.cheat` 编进二进制，一张不多一张不少；
  ③ `fuzzyScore` 打分逐行照抄（名称 1.0 / slug 0.9 / 分类 0.6，词首 +8、连续 +12）；
  ④ 「导入 `.cheat` 目录」原生兼容 —— 纯 navi 文件不需要改一个字就能被认出来。
  两处**有意**偏离（`cheat.rs` 模块头）：`$ var: <命令>` **不执行**（进程轨插件跑任意
  shell 超出授权面，只把命令列出来让用户自己跑）；变量不用「每个变量一个输入框」
  （声明式 IO 没有动态字段），改成 `branch=main message=修复 登录` 一行赋值。
- **文件比较 · 目录段**：参考页该段真正可用的只有三件东西，已逐件对上——
  ① 顶部「全部 / 差异 / 相同」→ `view` 参数（参考页只筛树的显示，工具没有树，筛在输出上）；
  ② 「导出报告 HTML / 文本 / Unified Diff」→ `format` 参数（`list` / `table` / `html`）；
  ③ 排除 ← 参考页**没有**这项能力，只硬编码跳过 `.` 开头的隐藏项，本仓补了
  `exclude`（同名 / 扩展名 / `*` 后缀三种写法，命中目录**剪枝**而不是过滤结果集）。
  ⚠️ 参考页的「导出报告」在**目录会话**下是空实现：`doExport` 读的是 `textRows`
  （文本 diff 的行），目录会话里它是空数组 ⇒ 导出空文件。这是参考仓的 bug，
  我们按它的**意图**补成三种形态，并在 `plugin.toml` 里写明。
- **文件比较 · 配置段**（本轮）：`DirCompare.vue` 的第三个会话类型已落成独立工具
  `配置比较`（`duck.compare.config-compare`，2 个输入框 + 2 个参数），四档口径
  （相同 / 修改 / 仅左 / 仅右）与参考页一致，并保留「仅差异 / 全部」筛选。
  两处**有意**偏离（都写在 `config_diff.rs` 模块头）：YAML 认缩进（参考仓逐行正则，
  两段的同名子键会被压成一个）、`[section]` 参与键路径（参考仓跳过段名，`[db]` 与
  `[mq]` 的 `url` 会撞车）。两者都是「参考仓那份会算错」的地方。
  ⚠️ 后端 `src-tauri/src/config_diff/`（1134 行）**不是**页面上这一段——它是按
  环境目录 + SSH + 忽略规则的另一套，页面没接，别被行数骗第三次。
- **数据格式转换**与 **CSV 工具**的职责重叠**不合并**：参考仓本来就是两个页面
  （`DataFormat.vue` 三段解析 / `CsvTableEditor.vue` 预览 + 图表），两份能力各归其位。
  数据格式转换补齐三段后，重叠面只剩「CSV → Markdown/JSON/INSERT」这一小块，
  与参考仓现状一致。
- **随机文本生成**的六类生成器全部落地，客户信息段按参考页的 CRS 报送版面输出。

### 两处**有意**不照抄的地方

| 参考页 | 这里 | 理由 |
|---|---|---|
| 「配置管理」弹窗 + `localStorage` 持久化（定长列宽、分隔符配置） | 一行文本参数 `10:姓名,8:城市,4:年龄` | process 轨插件拿不到宿主 kv；一行文本可复制存档、进版本库、贴交接文档，对团队反而更耐用 |
| 六类生成器各有两个按钮（「生成」/「批量生成」），同一类型走两段代码 | 一个 `count` 参数：`= 1` 走单次口径、`> 1` 走批量口径 | 与那两个按钮一一对应。例如「日期」单次=今天、批量=2000 年至今随机，语义差别照抄 |

## 五、结论

「功能没完全复刻」的判断成立，但**不是全局性的**：逐项对比过的 34 个工具里 27 个
参数面已经对齐（或参考页本来就小），重页面全部收口，只剩 **3 个需逐项核对的**
（HTTP 请求、SQL 合并、Class/Jar 比对）—— 它们不是「缺一整个页面」，而是
「按钮级能力还没逐个核对」。
